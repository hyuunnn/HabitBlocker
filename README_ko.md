# 습관 차단기

> 집중해야 할 때 특정 웹사이트 방문에 마찰을 더해 습관적 접속을 줄이는 macOS 메뉴 막대 유틸리티입니다.

**습관 차단기**는 `youtube.com` 또는 유튜브 영상 URL처럼 도메인이나 URL을 등록하고, macOS 메뉴 막대에서 차단 상태를 관리하는 도구입니다. 빠른 선택 및 직접 입력 집중 세션, 집중 세션 전용 해제 대기, 로컬 활동 요약, 선택적 집중 알림을 제공합니다.

[English README](README.md)

## Manus 1.6으로 제작

이 프로젝트는 **Manus 1.6**을 활용한 바이브 코딩 방식으로 제작되었습니다. 자연어 제품 요구사항을 바탕으로 제품 흐름, SwiftUI 메뉴 막대 인터페이스, 도메인 차단 로직, 리팩토링, 자동 테스트, 문서를 반복적으로 만들고 검증했습니다.

## 요구 사항

| 항목 | 내용 |
|---|---|
| 운영체제 | macOS 13 이상 |
| 빌드 도구 | Swift가 포함된 Xcode 또는 Xcode Command Line Tools |
| 권한 | 시스템 전체 차단 규칙을 적용하거나 제거할 때만 관리자 암호가 필요합니다. |

## 저장소 복제, 빌드, 테스트, 실행

저장소를 복제한 뒤 스크립트 실행 권한을 부여하고, 핵심 테스트와 앱 빌드를 실행한 다음 앱을 엽니다.

```zsh
git clone https://github.com/hyuunnn/HabitBlocker.git
cd HabitBlocker

chmod +x Scripts/build.sh Scripts/test.sh
./Scripts/test.sh
./Scripts/build.sh
open Build/HabitBlocker.app
```

앱을 실행하면 macOS 화면 상단 메뉴 막대에 방패 아이콘이 나타납니다. 아이콘을 누르면 제어 화면이 열립니다.

> 차단 규칙을 처음 적용할 때 macOS가 관리자 암호를 요청합니다. 습관 차단기는 네트워크 프록시 자동 설정만 변경하며, `/etc/hosts`를 포함한 시스템 파일은 수정하지 않습니다.

## 사용 방법

| 순서 | 할 일 |
|---|---|
| 1 | 메뉴 막대의 방패 아이콘을 누릅니다. |
| 2 | **차단 목록**에 `youtube.com` 같은 도메인을 넣거나 전체 URL을 붙여 넣습니다. |
| 3 | **등록 사이트 차단**을 켜면 즉시 규칙을 적용하고, 끄면 즉시 규칙을 제거합니다. |
| 4 | 빠른 시간 선택 또는 1~1,440분 직접 입력으로 집중 세션을 시작합니다. |
| 5 | 집중 세션을 끝낼 때는 설정한 해제 대기 시간이 지난 뒤 최종 해제를 확인합니다. |

일반 차단 토글은 즉시 반영되며, 해제 대기는 **집중 세션 종료에만** 적용됩니다.

## 차단 방식과 한계

습관 차단기는 보안 제품이 아니라 가벼운 행동 변화 도구입니다. 차단은 시스템 파일을 하나도 수정하지 않는 **시스템 프록시 자동 설정(PAC)** 방식으로 동작합니다.

### 동작 방식

| 단계 | 설명 |
|---|---|
| 1 | 앱이 차단 목록으로 PAC 스크립트를 만들고, 로컬호스트(127.0.0.1) 전용 리스너가 이 스크립트를 서빙합니다. |
| 2 | 네트워크 서비스의 프록시 자동 설정이 이 PAC URL을 가리킵니다. 적용·해제 시 관리자 암호를 한 번 묻고, 켜기 전 프록시 설정은 백업했다가 해제 때 복원합니다. |
| 3 | PAC은 차단 도메인만 로컬 리스너로 보내고, 리스너는 403 차단 화면으로 응답합니다. 나머지 트래픽은 전부 직접 연결(DIRECT)됩니다. |
| 4 | DNS와 `/etc/hosts`는 건드리지 않으므로 이름 해석이나 로컬 서비스가 망가질 일이 없습니다. 설정이 잘못되어도 최악의 결과는 "차단이 안 되는 것"입니다. |

브라우저의 보안 DNS(DoH)도 우회 경로가 아닙니다. PAC은 DNS 질의 전에 호스트명으로 판정하기 때문에, hosts 파일 방식보다 보안 DNS에 강합니다.

### 한계

| 한계 | 의미 |
|---|---|
| 앱 미실행 상태 | PAC을 서빙하는 로컬 리스너가 앱 안에 있으므로, 앱이 완전히 종료된 동안에는 차단이 일시적으로 풀립니다. 설정은 남아 있어 다시 실행하면 즉시 복구되고, 집중 타이머도 다음 실행 때 재조정됩니다. 장시간 차단을 유지하려면 메뉴 막대 앱을 실행 상태로 두세요(로그인 시 자동 실행 지원). |
| 시스템 프록시를 무시하는 클라이언트 | 대부분의 브라우저는 시스템 프록시를 따르지만, 일부 CLI 도구(curl 등)나 자체 프록시 설정을 강제하는 앱은 우회할 수 있습니다. |
| VPN | 시스템 프록시를 무시하는 VPN 클라이언트는 우회할 수 있습니다. |
| 기존 브라우저 연결 | 이미 열린 탭은 브라우저가 연결을 유지해 잠시 계속 보일 수 있습니다. 브라우저를 완전히 종료한 뒤 다시 열면 새 연결에 차단이 적용됩니다. |
| 포트 충돌 | 다른 프로그램이 47471 포트를 점유하면 차단 사이트가 브라우저 기본 오류 화면으로 표시될 수 있습니다. |

### 구버전에서 업그레이드한 경우

구버전(1.0)은 `/etc/hosts`에 차단 규칙을 기록했습니다. 새 버전은 hosts 파일을 수정하지 않으며, 남아 있는 이전 규칙은 앱이 자동으로 감지합니다. 다음 차단 적용·해제 때 같은 관리자 승인 안에서 이전 규칙을 제거하고 hosts 파일을 원래 내용으로 되돌립니다.

Apple은 `MenuBarExtra`를 지속적인 메뉴 막대 제어 요소로 안내하며, 메뉴 막대 전용 유틸리티는 `LSUIElement`를 사용해 Dock과 앱 전환기에서 숨길 수 있다고 설명합니다.[1] [2]
